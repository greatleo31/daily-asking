## ADDED Requirements

### Requirement: 发布必须经过分阶段人工门禁
仓库 SHALL 在关键 UI 实现前记录 G2 视觉验收，并在创建 Beta 或正式 Release 前记录 G3 产品验收；自动化检查不得替代人工批准。

#### Scenario: UI 尚未通过 G2
- **WHEN** 关键页面原型或多视口截图尚无项目负责人明确批准
- **THEN** 视觉实现任务不得被标记为人工验收完成

#### Scenario: 候选版本尚未通过 G3
- **WHEN** APK 可构建但核心验收脚本或项目负责人批准缺失
- **THEN** 仓库不得把该提交标记为已发布的 Beta 或正式 V1

### Requirement: 开源发布必须包含 MIT 与专业项目说明
仓库 SHALL 在 Beta 发布前包含 MIT `LICENSE`、中文 README、架构与数据流说明、真实界面截图、安装步骤、隐私边界、贡献入口、安全报告方式和已知限制。

#### Scenario: 审查者打开仓库首页
- **WHEN** 审查者阅读 Beta 对应提交的 README
- **THEN** 可以确认产品定位、核心闭环、实际界面、安装方式、AI 路径、数据边界、验证命令和许可证

#### Scenario: 截图尚未由真实应用产生
- **WHEN** 项目没有对应候选构建的真实界面截图
- **THEN** README 不得用占位图或概念图冒充已实现界面

### Requirement: Beta 与正式 V1 必须区分签名和声明
系统 SHALL 先以 `v0.2.0-beta` 提供验收候选；正式 `v1.0.0` APK MUST 使用仓库外提供的独立发布签名，且两者的签名姿态、升级兼容和限制必须写入发布说明。

#### Scenario: 发布 Beta 候选
- **WHEN** G3 批准 Beta 且 APK 仍使用调试或临时候选签名
- **THEN** Release 标题和说明明确标记 Beta，不宣称应用商店级正式包

#### Scenario: 发布正式 V1
- **WHEN** 创建 `v1.0.0` Release
- **THEN** APK 使用独立发布签名，签名凭据未进入仓库，并记录 APK SHA-256

### Requirement: 每个大功能必须独立交付验证证据
仓库 SHALL 按视觉、数据、每日闭环、AI、网关和发布拆分功能分支；每个分支保存其 OpenSpec 任务、1 至 2 组最高风险自动化测试或等价既有测试证据、静态检查结果和人工验收项。

#### Scenario: 数据迁移功能准备合并
- **WHEN** 本地数据分支申请合入主分支
- **THEN** 变更中包含幂等/失败安全的关键测试证据以及旧数据人工验收结果

#### Scenario: 纯视觉功能准备合并
- **WHEN** 视觉分支申请合入主分支
- **THEN** 变更中包含多视口真实截图、交互状态验收和静态检查结果，不用大量低价值测试替代视觉验收
