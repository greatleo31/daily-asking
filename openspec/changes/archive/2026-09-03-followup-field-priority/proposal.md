## Why

今日保存后追问曾总先问「结果」，且答完/跳过后今日页不再连续出下一问，用户补不全证据字段；同时「跳过」与「稍后」语义重合，增加干扰。需要：缺字段按新优先级选问，并在今日页连续追完；操作只保留跳过与回答。

## What Changes

- 缺字段优先级：**背景 → 行动 → 结果 → 难点 → 个人贡献**（已部分落地，保留）
- 仍缺字段才问；**每一次生成决策仍最多一问**（屏幕上同时只展示一张卡）
- **今日页连续追问**：用户回答或跳过当前卡后，立刻为同一 Entry 生成并展示下一缺字段卡，直到无可追问（字段已齐或剩余 kind 均已 skip/answered）
- 「个人贡献」保持可追问（无独立字段）；答过或跳过即不再问
- **去掉「稍后」**；追问卡只保留「跳过」与「回答」（跳过 = 本条该 kind 不再问）
- 不改题干措辞、原因文案语气、卡片视觉排版大改（另刀）

## Non-goals

- 不改各 `QuestionKind` 的题干/`reason` 去 AI 味文案（另刀）
- 不大改卡片视觉层级/疏密/动效（另刀）
- 不一次叠多张追问卡；不是并行多问，是串行连续
- 不新增 Entry 字段、不多模态、不加每日任务/推送
- 不改 BYOK、出站披露、存储介质

## Capabilities

### New Capabilities

- `local-followup-questions`: 本地追问选问优先级、每次决策最多一问、今日页答/跳后连续出下一问、去掉稍后只留跳过、贡献可追问且答/跳即停

### Modified Capabilities

- （无强制修改既有主规格名）门面仍经 AppState；本 change 以 `local-followup-questions` 承载行为契约

## Impact

- **页面**：今日（保存后、答/跳后的追问卡连续出现）；证据详情若展示同卡，须同步去掉「稍后」
- **模块**：`question_engine`（优先级，已有）；今日页/追问卡 UI 与 AppState 在答/跳成功后再次调用生成并展示下一问；移除 `later` 入口
- **模型**：仍用 Entry / EvidenceQuestion / EvidenceAnswer；可不删枚举值 `later`（兼容旧数据），但 UI SHALL NOT 再提供「稍后」
- **隐私 / BYOK**：不涉及网络与出站
- **测试**：引擎序 + 连续链（答/跳后再次 next）+ 无稍后按钮的 Widget/行为测；亮深色截屏
