## Context

见修订后 `proposal.md`。引擎优先级已改为 context→action→result→blocker→contribution。缺口在今日页：答/跳后未立刻展示下一问；UI 仍露出「稍后」，与「跳过」重合。

分层：UI → AppState(Provider) → question_engine 纯逻辑 → StorageService。

## Goals / Non-Goals

**Goals**
- 答/跳成功路径上，AppState（或今日页编排）再次调用 `nextQuestion` 并打开/替换为下一张卡
- 去掉「稍后」入口；skip 语义保持本条 kind 不再问
- 首屏输入框与保存仍在；连续追问不挤掉主记录路径

**Non-Goals**
- 不重做卡片视觉疏密/去 AI 文案（另刀）
- 不并行多卡
- 不强制删除持久化中历史 `later` 状态值（只停用入口）；若需迁移可标可选

## Decisions

### 1. 连续链放在答/跳成功之后的编排，不塞进引擎一次返回多问

- **选择**：引擎仍每次 0/1 问；今日页在 answer/skip 持久化成功后立刻再 `nextQuestion`，有则展示。
- **理由**：符合「每次决策最多一问」+「串行连续」；单测可分层。
- **备选**：引擎返回队列 —— 否决，增加状态复杂度。

### 2. 展示形态

- **选择**：同一追问 bottom sheet/卡替换为下一问（或关闭后立即再开下一问），用户感知为连续。
- **样式**：[待用户选择] 若实现时需在「替换」vs「关再开」间选交互细节，先最小可用；本 design 不锁动画。
- **备选**：跳到证据详情 —— 否决，用户要求今日页连续。

### 3. 去掉稍后

- **选择**：追问卡 UI 移除稍后按钮；不再把 status 设为 `later`。历史 `later` 记录：下次选问时视为可再问或视为 skip —— **默认视为可再问（不永久排除）**，与 skip 区分；本 change 不提供稍后入口即可。
- **理由**：消除重合；最小改动。
- **备选**：把旧 later 全部当 skip —— 可能过激，除非用户另定。

### 4. 证据详情

- **选择**：若详情复用同一 QuestionCard，同步去掉稍后，避免双入口不一致。

## Risks / Trade-offs

- [连续追问疲劳] → 仍每次一问、可 skip 终止该 kind；全 skip 后停止。
- [与旧「不链式」截屏观察冲突] → 规格已改，验收改为「跳过后今日必须出下一问」。
- [旧 later 数据] → 不提供入口；选问不把 later 当 skip，除非另开刀。

## Migration Plan

- 无 schema 迁移。
- 回滚：恢复不自动连弹 + 恢复稍后按钮（不推荐）。

## Open Questions

无（「替换 vs 关再开」允许实现时取最小路径，不改变 specs）。
