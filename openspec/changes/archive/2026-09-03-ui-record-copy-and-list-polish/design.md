## Context

见 proposal。用户已用截屏指定目标结构。followup-field-priority 追问逻辑不在本 change 改动范围。

分层：UI 文案与列表组件 → 既有 AppState 数据（完整度、待补充状态）只读展示调整。

## Goals / Non-Goals

**Goals**：五条可见改动按 specs 落地；底栏改名；亮深色可读。  
**Non-Goals**：不改追问引擎；不改内部 API/存储键名强制重命名；不处理 ADB Keyboard。

## Decisions

### 1. 「证据→记录」只改用户可见层
- 代码标识、路由名、分析用字符串可不改；所有 `Text`/`AppLocalizations`/硬编码中文用户串改「记录」。
- 底栏标签同步改。

### 2. 待补充卡
- 主标题绑定 kind 短名映射表（与现有小字种类一致）。
- 右侧 `Container`/`Chip` 状长方框：已答绿 / 待补充红；去掉行内「·已答」前缀点样式。
- 样式细节以用户截屏意图为准，不另发明色板（用现有主题绿/错红色语义）。

### 3. 今日沉淀
- 单行 Text；删除原双块布局组件。

### 4. 列表圆标
- 增大直径与字号约束；用 FittedBox 或降字号保证 100% 不溢出。

### 5. 切片顺序（墨工按组 apply）
1) 文案证据→记录 + 占位 + 沉淀一行  
2) 待补充卡结构  
3) 列表去完整度小字 + 圆标加大  
每组留白截屏，工笔过目；全部过完交用户总 0.7。

## Risks

- [漏网「证据」文案] → 全局搜中文「证据」+ 截屏四页走查。
- [底栏改名认知] → 用户已确认。
