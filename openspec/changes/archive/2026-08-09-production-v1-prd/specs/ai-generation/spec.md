## Purpose

定义 BYOK AI 生成能力：只基于用户选中的记录，生成保持事实边界的追问、简历要点、周报和面试追问卡。

## ADDED Requirements

### Requirement: AI 服务商配置由用户控制
系统 SHALL 允许用户配置兼容 OpenAI 接口的服务商，包括服务商名称、基础地址、模型和 API Key，并 SHALL 允许用户清除该配置。

#### Scenario: 保存服务商配置
- **WHEN** 用户保存服务商名称、基础地址、模型和 API Key
- **THEN** 系统报告服务商已配置，且不以明文展示 API Key

#### Scenario: 清除服务商配置
- **WHEN** 用户清除 AI 配置
- **THEN** 后续真实 AI 生成不可用，直到用户重新提供有效配置

### Requirement: AI 请求必须要求来源选择和出站披露
系统 SHALL 在发送任何真实 AI 请求前，要求用户可见的来源选择和出站披露。

#### Scenario: 确认出站 AI 请求
- **WHEN** 用户请求基于选中记录生成 AI 内容
- **THEN** 系统在发送请求前展示服务商、模型、调用路径、选中来源字段和确认操作

#### Scenario: 未选择来源
- **WHEN** 用户未选择任何可用记录就尝试 AI 生成
- **THEN** 系统阻止请求，并要求用户选择或创建来源材料

### Requirement: AI 上下文必须最小化且任务相关
系统 SHALL 只发送当前 AI 任务所需字段，并 SHALL NOT 默认发送完整记录池。

#### Scenario: 从单条记录生成
- **WHEN** 用户从一条选中记录生成简历要点
- **THEN** 请求上下文仅限该记录和简历要点生成所需提示词

#### Scenario: 生成周报
- **WHEN** 用户从指定日期范围或选中记录生成周报
- **THEN** 请求上下文仅限选中范围或记录，并排除无关记录

### Requirement: AI 输出必须保持事实边界
系统 SHALL 要求 AI 输出根据所选产物类型区分可用内容、缺失证据、追问问题和风险提示。

#### Scenario: 缺少可量化结果
- **WHEN** 选中记录不包含可量化结果
- **THEN** 生成内容将缺失结果标记为信息缺口，而不是编造指标

#### Scenario: 服务商输出不受支持
- **WHEN** 服务商返回空内容、畸形内容或不符合契约的输出
- **THEN** 系统报告输出不可用，且不保存为成功产物

### Requirement: 支持的产物类型必须明确
系统 SHALL 将追问、简历要点、周报和面试追问卡作为不同的 AI 生成任务支持。

#### Scenario: 追问生成
- **WHEN** 用户为选中记录生成追问
- **THEN** 输出包含用于补足事实缺口的问题和提问原因

#### Scenario: 简历要点生成
- **WHEN** 用户从选中记录生成简历要点
- **THEN** 输出包含简洁要点、缺失字段、面试追问和风险提示

#### Scenario: 周报生成
- **WHEN** 用户从多条记录生成周报
- **THEN** 输出将工作归入可写入周报的分组，并标记证据不完整处

#### Scenario: 面试追问卡生成
- **WHEN** 用户从选中记录生成面试追问卡
- **THEN** 输出包含开场回答、可能追问、回答角度和证据缺口

### Requirement: AI 错误必须可操作
系统 SHALL 将常见服务商失败映射为清晰的用户可见状态，且不暴露密钥或原始凭据。

#### Scenario: API Key 无效
- **WHEN** 服务商返回认证或权限失败
- **THEN** 系统提示用户检查服务商凭据，且不记录或展示 API Key

#### Scenario: 服务商限流
- **WHEN** 服务商报告限流
- **THEN** 系统提示用户稍后重试，并保持现有记录和产物不变
