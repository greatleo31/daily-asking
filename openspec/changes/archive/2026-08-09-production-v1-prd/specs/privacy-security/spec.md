## Purpose

定义隐私与安全要求，确保 Daily Asking 保持本地优先、清晰披露 AI 出站数据，并安全支持 BYOK 使用。

## ADDED Requirements

### Requirement: 应用在无网络时仍可使用
系统 SHALL 在没有网络访问、AI 服务商配置或后端账号时，保持核心记录管理可用。

#### Scenario: 未配置 AI 的首次使用
- **WHEN** 用户在未配置 AI 的情况下打开应用
- **THEN** 用户可以确认隐私边界并管理本地记录

#### Scenario: 网络不可用
- **WHEN** 网络访问不可用
- **THEN** 本地记录仍可读取和编辑，而真实 AI 生成不可用

### Requirement: 密钥必须与记录和日志隔离
系统 SHALL 将 API Key 与记录、产物、导出包、日志和迁移包分开存储。

#### Scenario: 日志脱敏
- **WHEN** 应用记录诊断信息
- **THEN** API Key、令牌、密钥、提示词和超长用户内容被省略或脱敏

#### Scenario: BYOK 设置后导出
- **WHEN** 用户在保存 API Key 后导出数据
- **THEN** 导出内容不包含 API Key、令牌、安全存储密钥值或用于凭据检索的密钥别名

### Requirement: 真实 AI 调用必须进行出站披露
系统 SHALL 在每次真实 AI 调用前披露将离开设备的数据。

#### Scenario: 生成前披露
- **WHEN** 用户发起真实 AI 生成任务
- **THEN** 系统在用户确认前列出服务商、路径、选中字段和非上传保证

#### Scenario: 用户取消披露
- **WHEN** 用户取消出站披露
- **THEN** 不发送 AI 请求，且本地数据保持不变

### Requirement: 生成内容不得编造职业证据
系统 SHALL 将无依据声明、编造数字、编造公司名、编造项目名和编造职责视为无效输出风险。

#### Scenario: 输出包含无依据指标
- **WHEN** 生成内容包含选中来源记录中不存在的指标
- **THEN** 系统展示风险或验证失败，而不是将其呈现为已验证证据

#### Scenario: 输出追问缺失事实
- **WHEN** 证据不完整
- **THEN** 系统鼓励追问或缺失字段说明，而不是编造完整成果

### Requirement: 隐私边界必须在首次引导和发布文档中可见
系统 SHALL 在首次引导和发布文档中说明本地优先存储、BYOK 行为、最小出站上下文和已知限制。

#### Scenario: 首次引导隐私边界
- **WHEN** 用户首次打开应用
- **THEN** 应用说明记录本地优先，且 AI 调用只会在用户确认后发送选中任务上下文

#### Scenario: 发布文档
- **WHEN** 用户阅读 GitHub Release 或 README
- **THEN** 文档说明哪些数据保存在本地、哪些数据可能发送给 AI 服务商，以及哪些能力不在范围内
