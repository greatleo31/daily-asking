## 上下文

详见 `proposal.md` 中的动机和产品范围。当前代码库是 Flutter Android 应用，使用 Riverpod 状态控制器、GoRouter 路由、基于 `shared_preferences` 的本地记录持久化、基于 `flutter_secure_storage` 的 BYOK 设置、`assets/` 中的提示词模板、模拟大模型客户端，以及尚未完全接入生成界面的兼容 OpenAI 接口客户端。

本变更是单机全栈：APK 是产品表面，本地存储是数据层，兼容 OpenAI 接口的服务商是外部 API 依赖，GitHub Release 是运维发布表面。现有 Cloudflare Worker 网关不进入 v0.1 生产路径。

## 目标 / 非目标

**目标：**

- 让应用在离线状态下仍可完成记录 CRUD、搜索、筛选和导出。
- 通过明确 BYOK 服务商配置和发送前披露来路由真实 AI 生成。
- 在把提示词输出当作产物前进行校验，保持事实边界。
- 通过 CI、APK 构建证据、README、隐私文档和发布说明，让发布就绪可重复。
- 控制实现体量，使其适合按 OpenSpec 实施任务增量推进。

**非目标：**

- 不做云账号、同步后端、托管模型代理、管理后台、支付或应用商店发布。
- v0.1 不集成生产级 Worker 网关。
- 除非后续规格变更存储隐私要求，否则不引入完整记录数据库加密。

## 决策

### 1. 使用本地仓库边界管理记录和产物数据

记录和生成产物应通过仓库接口访问，而不是由 UI 页面直接读写。现有 `Entry` 和 `Artifact` 领域对象继续作为行为词汇；持久化细节未来可从 `shared_preferences` 切换到更耐久的本地存储，而不改变规格。

备选方案：

- 继续把所有本地数据放在 `shared_preferences`：最快，但对搜索、筛选、导出增长和损坏数据恢复较弱。
- 立即引入本地数据库：长期数据模型更好，但会增加迁移和依赖成本。只有当实现确认 `shared_preferences` 无法安全满足 v0.1 搜索/导出时再使用。

### 2. BYOK 直连是 v0.1 唯一真实 AI 路径

生成界面只应在测试/演示回退时使用模拟客户端；只有用户保存服务商配置并确认出站披露后，才使用兼容 OpenAI 接口的客户端。Worker 网关必须保持可见的非目标状态，避免误引入服务端责任。

备选方案：

- 官方网关：有集中控制能力，但需要认证、邀请码校验、限流、密钥运维、日志和部署就绪。
- 只发布模拟演示：更容易，但无法满足用户自配置 AI 生成的产品承诺。

### 3. 把提示词输出契约作为校验门

提示词模板已经定义输出契约。生成流程应根据所选产物契约解析服务商输出，再保存或展示为成功产物。非法 JSON、空内容或缺少必要字段都应变成用户可操作的错误。

备选方案：

- 直接展示模型原文：最快，但不适合依赖真实证据和结构化产出的产品。
- 在页面中硬编码解析逻辑而不依赖提示词元数据：初期简单，但容易造成提示词与结构契约漂移。

### 4. 每次真实 AI 发送前都使用明确披露状态

发送给真实服务商前，UI 应展示服务商、模型、路径、选中字段、来源记录数量/日期范围，以及不会包含无关记录的保证。用户取消时不得发起请求。

备选方案：

- 只在首次引导展示一次：不足以覆盖每个 AI 任务的不同出站数据。
- 把披露藏在设置里：更容易，但不满足最小出站上下文要求。

### 5. 将 GitHub Release 定义为预览生产，而不是应用商店生产

v0.1 发布就绪意味着可下载 APK、CI 证据、文档、隐私说明和已知限制。如果仍使用调试签名，发布文档必须声明它是 GitHub 预览 APK，而不是应用商店级生产包。

备选方案：

- 应用商店级签名和政策包：更完整，但超出本次范围。
- 仅作为作品集仓库：弱于用户要求的生产级 GitHub Release。

## 模块边界

- 前端：首次引导、记录编辑/列表、产物生成、设置、导出 UI、错误/空/加载状态。
- 数据：记录和产物仓库、本地持久化、导入/导出包校验、结构版本迁移处理。
- API：仅使用兼容 OpenAI 接口的聊天补全接口；请求上下文必须由选中的来源记录和提示词模板组装。
- 后端：v0.1 无自有生产后端；网关代码可以保留，但不得呈现为已配置生产路径。
- 测试：领域/单元测试、仓库测试、大模型客户端/错误映射测试、核心流程组件测试、CI 发布检查。
- 运维：GitHub Actions、APK 构建、发布说明、README/隐私文档、签名姿态和密钥扫描。

依赖方向保持为 UI → 控制器/应用服务 → 仓库/客户端 → 平台或外部服务商。UI 不得直接读取安全密钥，只能通过设置/生成应用层访问。

## 数据与迁移计划

- 保持 `Entry` 字段语义稳定：id、date、task、context、action、result、blocker、tags、createdAt、updatedAt。
- 只有在定义输出校验后才新增产物持久化，字段包含来源记录 id、类型、内容、提示词版本、模型信息和 createdAt。
- 为导出包和任何本地结构迁移引入存储版本。
- 对已有 `daily_asking.entries.v1` 用户，在迁移到任何新本地存储前先加载并保留当前记录。
- 如果迁移失败，展示恢复/错误状态，且不要覆盖原始存储载荷。
- v0.1 回滚是源码级回滚：因为没有远程迁移，回滚意味着保持旧本地载荷可读，或在迁移失败时保持旧载荷不变。

## 安全、日志和观测

- API Key 值只能流经安全存储和请求授权头。
- 日志必须省略 API Key、令牌、提示词、长用户内容，以及可能包含用户数据的服务商响应。
- 导出包和迁移包必须排除服务商密钥值，以及用于凭据检索的密钥别名。
- 用户可见错误应包含足够操作指引，但不能暴露原始密钥或完整服务商载荷。
- v0.1 观测以本地和 CI 为主：测试输出、构建日志、发布说明和安全调试日志。不需要远程遥测。

## 失败模式

- 本地数据无法解析 → 展示本地数据加载失败，避免自动覆盖，并在可行时提供导出/恢复路径。
- 本地保存/导出失败 → 保持内存状态与持久化状态一致，并展示可重试错误。
- AI 未配置 → 阻止真实生成，并引导用户到设置或演示模式。
- API Key 无效/无权限 → 展示凭据操作错误并脱敏凭据。
- 服务商限流/网络超时 → 展示稍后重试状态，并保持现有记录和产物不变。
- 服务商返回空内容或非法 JSON → 展示不可用输出状态，不保存为成功产物。
- CI/构建因缺少 Flutter 不可用 → 文档化前置条件，不声明发布验证完成。

## 上线与发布计划

1. 在 `feature/production-prd-sdd` 落地 OpenSpec PRD、设计和任务。
2. 按 `tasks.md` 在小功能分支或后续提交中实现。
3. 在声明发布就绪前新增 CI。
4. 产出 APK 构建证据，并更新 README、隐私文档和发布说明。
5. 只有在静态检查、测试和构建证据齐全后，才打 GitHub 预览发布标签。
