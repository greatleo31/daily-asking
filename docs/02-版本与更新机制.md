# 版本与更新机制（v1.1+）

> 本文描述版本号管理、更新清单协议、客户端检查/下载/安装流程与发布脚本。
> 代码注释引用本文时，小节编号对应「§x」。

## 1. 目标

- 版本号单一来源，避免 versionName / versionCode 脱节。
- 客户端能发现新版本、引导或自动安装 APK。
- 演示环境可本地起 HTTP 服务复现；生产环境切换 HTTPS 直链。

## 2. 版本号

### 2.1 单一来源

- 展示名：`kAppVersionName`（例 `1.1.1`），更新判定：`kAppVersionCode`（例 `10101`）。
- 两者都定义在 `lib/core/version.dart`，并与 `pubspec.yaml` 的 `version: <name>+<code>` 保持同步。
- 提升版本只允许使用 `scripts/bump-version.sh <major.minor.patch>`，禁止手改。

### 2.2 versionCode 映射

```
versionCode = major * 10000 + minor * 100 + patch
```

例：`1.1.1 -> 10101`、`1.2.0 -> 10200`。必须单调递增，客户端禁止降级。

## 3. 更新清单协议（latest.json）

### 3.1 请求

```
GET {kUpdateBaseUrl}/latest.json?platform=android&channel=stable&vc={当前versionCode}
```

- `kUpdateBaseUrl` 默认 `http://127.0.0.1:8090`（演示，配合 `adb reverse tcp:8090 tcp:8090`）。
- 生产环境用 `--dart-define=UPDATE_BASE_URL=https://update.<domain>` 注入 HTTPS 地址。
- 请求超时 10s；非 200 或解析失败按「检查失败」处理（自动检查静默，手动检查提示）。

### 3.2 响应字段（只增不改删）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `versionCode` | int | 是 | 服务端版本；`<=` 当前视为无更新 |
| `versionName` | string | 是 | 展示版本名 |
| `url` | string | 是 | APK 直链；生产必须 HTTPS |
| `changelog` | string | 否 | 更新日志（Markdown），空显示默认文案 |
| `mandatory` | bool | 否 | 是否强制更新，默认 `false` |
| `releaseDate` | string | 否 | 发布日期 `YYYY-MM-DD` |
| `sha256` | string | 否 | APK SHA-256，下载完成后校验 |
| `minVersionCode` | int | 否 | 最低可升级版本 |

客户端容忍缺字段与未知字段；`versionCode` / `versionName` / `url` 缺失或类型非法 → 解析失败（按检查失败处理，不崩溃）。

## 4. 客户端流程

### 4.1 检查入口

| 入口 | 触发 | 行为 |
| --- | --- | --- |
| 关于页「检查更新」 | 手动 | 弹窗展示结果（无更新 / 有新版本 / 失败） |
| AppShell 启动 | 自动（延迟 4s） | 强制→弹不可关闭框；非强制+开启自动更新→直接下载；其余静默 |
| 设置「自动更新」 | 开关 | 默认关；开启后启动自动下载安装 |

### 4.2 决策

- `NoUpdate`：服务端 `versionCode <= 当前`。
- `UpdateAvailable(info)`：有更新；按 `info.mandatory` 决定弹窗可关闭性（强制 `PopScope(canPop:false)`）。
- `UpdateCheckFailed(reason)`：网络 / HTTP / 解析失败。

### 4.3 下载与安装（Android 原生侧）

`MethodChannel com.dailyasking.daily_asking/update` → `downloadAndInstall(url, fileName, sha256, title)`：

1. `DownloadManager` 入队，通知栏展示进度（`VISIBILITY_VISIBLE_NOTIFY_COMPLETED`）。
2. 下载目录：`getExternalFilesDir(DIRECTORY_DOWNLOADS)`（无需存储权限），文件名 `liuhen-<versionName>.apk`。
3. 完成广播：`ACTION_DOWNLOAD_COMPLETE` 是系统保护广播，必须**动态注册** receiver。
4. `sha256` 非空时校验本地文件，不匹配则删除并提示重试。
5. 安装：自定义 `UpdateFileProvider`（authority `${applicationId}.fileprovider`，只暴露本应用 Download 目录）+ `ACTION_VIEW` 引导系统安装页。
6. Android 8+ 未授权「安装未知应用」时，先引导 `ACTION_MANAGE_UNKNOWN_APP_SOURCES` 设置页。

## 5. 网络安全

- `android/app/src/main/res/xml/network_security_config.xml`：base 默认禁明文，仅放行 `127.0.0.1`（演示更新源）。
- 生产环境必须使用 HTTPS 直链（`UPDATE_BASE_URL` 注入），避免中间人篡改 APK。

## 6. 发布脚本

### 6.1 bump-version.sh

```bash
sh scripts/bump-version.sh 1.2.0
```

同步修改 `pubspec.yaml` 与 `lib/core/version.dart`（CRLF 安全，Windows git-bash 可用）。

### 6.2 generate-latest-json.sh

```bash
sh scripts/generate-latest-json.sh build/app/outputs/flutter-apk/app-release.apk "更新说明" [--mandatory]
```

读取 `lib/core/version.dart` 生成 `build/latest.json`，`sha256` 用 python 计算（避免 Windows 无 `sha256sum`）。

### 6.3 本地演示

```bash
# 主机
python -m http.server 8090 --bind 127.0.0.1 --directory build/update-serve
# 设备
adb reverse tcp:8090 tcp:8090
```

## 7. 已知限制

- Release 构建目前使用 debug 签名（便于本机/演示安装）。正式发布前应接入独立发布签名（见 `docs/release-signing.md` 思路），并同步更新 `latest.json` 的 `sha256`。
- 下载采用系统 DownloadManager，行为受系统通知渠道管理；安装后由用户点通知或系统安装页完成。
