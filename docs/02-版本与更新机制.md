# 版本与更新机制（v1.1+）

> 本文描述版本号管理、更新清单协议、客户端检查/下载/安装流程与发布脚本。
> 代码注释引用本文时，小节编号对应「§x」。

## 1. 目标

- 版本号单一来源，避免 versionName / versionCode 脱节。
- 客户端能发现新版本、引导或自动安装 APK。
- 演示环境可本地起 HTTP 服务复现；生产环境切换 HTTPS 直链 + 多镜像回退。

## 2. 版本号

### 2.1 单一来源

- 展示名：`kAppVersionName`（例 `1.2.2`），更新判定：`kAppVersionCode`（例 `10202`）。
- 两者都定义在 `lib/core/version.dart`，并与 `pubspec.yaml` 的 `version: <name>+<code>` 保持同步。
- 提升版本只允许使用 `scripts/bump-version.sh <major.minor.patch>`，禁止手改。

### 2.2 versionCode 映射

```
versionCode = major * 10000 + minor * 100 + patch
```

例：`1.2.2 -> 10202`。必须单调递增，客户端禁止降级。

## 3. 更新清单协议（latest.json）

### 3.1 请求

```
GET {base}/latest.json?platform=android&channel=stable&vc={当前versionCode}
```

- 支持配置多个更新基址（`UPDATE_BASE_URLS`，逗号/分号/换行分隔）；首个为主镜像，其余为回退镜像。
- 默认不配置；未配置时客户端不发起网络请求。生产环境用构建注入（推荐直接用
  `scripts/build-release.sh`，避免手工拼参数漏注入）：
  `--dart-define=UPDATE_BASE_URLS=https://gitee.com/yankehu/daily_asking/raw/main/update,https://github.com/greatleo31/daily-asking/releases/latest/download`
  （首源必须是大陆可达的 HTTPS 稳定清单基址；GitHub Release 只能作第二回退源）。
- 兼容单源注入 `--dart-define=UPDATE_BASE_URL=https://update.<domain>`（`UPDATE_BASE_URLS` 优先）。
- **基址必须是稳定目录或稳定别名**（`…/update/latest.json`，或 GitHub 的
  `…/releases/latest/download/latest.json`），不要指向 app-version 专属 release tag 目录
  （`…/releases/download/v1.2.3/…`），否则旧 APK 会一直读到旧清单。
- **每个镜像各配一份自己的 `latest.json`，且 `url` 指向同镜像的 APK**（Gitee 清单 → Gitee 附件，
  GitHub 清单 → GitHub 附件）。两处若内容相同、`url` 都写 Gitee，Gitee 不可达时回退源
  只能给出一份「下载地址也不可达」的清单，回退等于失效。
- 每次检查并发请求全部源、每源独立超时 6s；存在任一合法清单即成功，取所有合法清单中
  versionCode 最高者；多源同版本时取配置顺序靠前源的清单（含其 APK `url`）。
- 非 200 / 超时 / 解析失败按该源失败处理；全部源失败才提示「所有更新源检查失败」（自动检查静默，手动检查提示）。

### 3.2 响应字段（只增不改删）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `versionCode` | int | 是 | 服务端版本；`<=` 当前视为无更新 |
| `versionName` | string | 是 | 展示版本名 |
| `url` | string | 是 | APK 直链；生产必须 HTTPS，且与 `latest.json` 在同一镜像 |
| `changelog` | string | 否 | 更新日志（Markdown），空显示默认文案 |
| `mandatory` | bool | 否 | 是否强制更新，默认 `false` |
| `releaseDate` | string | 否 | 发布日期 `YYYY-MM-DD` |
| `sha256` | string | 否 | APK SHA-256，下载完成后校验 |
| `minVersionCode` | int | 否 | 最低可升级版本；当前 `versionCode` 低于它即视为强制更新 |

客户端容忍缺字段与未知字段；`versionCode` / `versionName` / `url` 缺失或类型非法 → 解析失败（按检查失败处理，不崩溃）。

## 4. 客户端流程

### 4.1 检查入口

| 入口 | 触发 | 行为 |
| --- | --- | --- |
| 关于页「检查更新」 | 手动 | 更新源未配置时直接提示，不发起网络；已配置时并发查询远端版本清单 |
| AppShell 启动 | 自动（延迟 4s） | 仅更新源已配置时检查；强制/低于 `minVersionCode`→弹不可关闭框；非强制+开启自动更新→直接下载；非强制+关闭自动更新→轻提示一次（可点「查看」打开更新框） |
| 设置「自动更新」 | 开关 | 默认关；更新源已配置且发现新版本后自动下载安装 |

### 4.2 决策

- `NoUpdate`：所有合法清单的最高 `versionCode <= 当前`。
- `UpdateAvailable(info)`：有更新；按 `info.isMandatoryFor(当前 versionCode)`（显式 `mandatory`，或当前版本低于 `minVersionCode`）决定弹窗可关闭性（强制 `PopScope(canPop:false)`，且「立即更新」带防重复点击）。
- `UpdateCheckFailed(reason)`：未配置 / 全部源网络 / HTTP / 解析失败。

### 4.3 下载与安装（Android 原生侧）

`MethodChannel com.dailyasking.daily_asking/update` → `downloadAndInstall(url, fileName, sha256, title)`：

1. `DownloadManager` 入队，通知栏展示进度（`VISIBILITY_VISIBLE_NOTIFY_COMPLETED`）。
2. 下载目录：`getExternalFilesDir(DIRECTORY_DOWNLOADS)`（无需存储权限），文件名 `liuhen-<versionName>.apk`。
3. 完成广播：`ACTION_DOWNLOAD_COMPLETE` 是系统保护广播，必须**动态注册** receiver。
4. `sha256` 非空时校验本地文件，不匹配则删除并提示重试。
5. 安装：自定义 `UpdateFileProvider`（authority `${applicationId}.fileprovider`，只暴露本应用 Download 目录）+ `ACTION_VIEW` 引导系统安装页。
6. Android 8+ 未授权「安装未知应用」时，先引导 `ACTION_MANAGE_UNKNOWN_APP_SOURCES` 设置页。

## 5. 网络安全

- `android/app/src/main/res/xml/network_security_config.xml`：base 默认禁明文，仅放行 `127.0.0.1`（演示更新源）。
- 生产环境必须使用 HTTPS 直链（`UPDATE_BASE_URLS` 注入），避免中间人篡改 APK。

## 6. 发布脚本

### 6.1 bump-version.sh

```bash
sh scripts/bump-version.sh 1.2.0
```

同步修改 `pubspec.yaml` 与 `lib/core/version.dart`（CRLF 安全，Windows git-bash 可用）。

### 6.2 generate-latest-json.sh

```bash
# 本地演示（url 写 http://127.0.0.1:8090/<apk>）
sh scripts/generate-latest-json.sh build/app/outputs/flutter-apk/app-release.apk "更新说明" [--mandatory]

# 生产发布（url 写死为镜像 HTTPS 直链，与 latest.json 同镜像）
sh scripts/generate-latest-json.sh build/app/outputs/flutter-apk/app-release.apk "发布说明" \
    --asset-url https://<mirror>/update/v1.2.3/app-release.apk \
    --out build/update-gitee/latest.json
```

- `versionCode` / `versionName` 由 `scripts/apk_version.py` **直接从 APK 内的
  AndroidManifest.xml 读取**（纯 Python，不需要 aapt/Android SDK），并与
  `lib/core/version.dart` 交叉校验：两者不一致时脚本**报错退出**。
  APK 才是用户真正装到手机上的东西，清单必须描述它；源码里的版本号只描述工作区状态，
  构建时用 `--build-number` / 改了源码没重新出包都会让二者脱节。
  确认要放行不一致时加 `--allow-mismatch`（会打印警告，清单按 APK 生成）。
- `sha256` 用 python 计算（避免 Windows 无 `sha256sum`）；`--out` 缺省 `build/latest.json`
  并自动创建父目录；`--asset-url` 缺省保留本地演示地址。
- `--out` 指向 `update/latest.json`（即仓库里那份已发布清单）时多一道**护栏**：
  新清单 `versionCode` **低于**该文件现有值 → 报错退出（客户端只按 `versionCode` 判定，
  清单回退会让所有已发布用户一律看到「无更新」）；`versionCode` 相同但 `sha256` 变了 →
  打印警告后照常生成（内容改了却不升版本号，已装旧包的用户不会收到这次更新）。
  输出到其它路径（如各镜像的 `build/update-*/latest.json`）不受此护栏影响。

### 6.3 本地演示

```bash
# 主机
python -m http.server 8090 --bind 127.0.0.1 --directory build/update-serve
# 设备
adb reverse tcp:8090 tcp:8090
```

### 6.4 生产发布步骤（每次发版必做）

1. 用 `scripts/build-release.sh` 构建 release APK（更新源已固化注入，不会漏），确认 `kAppVersionCode` 单调递增。
2. 核对 **APK 的真实版本号**：`python scripts/apk_version.py build/app/outputs/flutter-apk/app-release.apk`
   必须与 `lib/core/version.dart`、`pubspec.yaml` 一致（第 3 步的脚本也会自动校验，不一致直接报错）。
3. 给**每个镜像各生成一份** `latest.json`，`--asset-url` 写该镜像自己的 APK 直链：
   - 主镜像（Gitee）：`sh scripts/generate-latest-json.sh build/app/outputs/flutter-apk/app-release.apk "发布说明" --asset-url https://gitee.com/yankehu/daily_asking/releases/download/v<版本>/liuhen-<版本>.apk --out update/latest.json`
   - 回退镜像（GitHub）：同上，但 `--asset-url https://github.com/greatleo31/daily-asking/releases/latest/download/app-release.apk --out build/update-github/latest.json`
4. 上传产物：APK 与**该镜像自己的 `latest.json`** 一起作为 Release 附件上传。
   GitHub 回退基址是 `…/releases/latest/download`，**Release 里缺 `latest.json` 附件回退源就查不到更新**；
   该别名要求 APK 附件名固定（现用 `app-release.apk`），改名会让回退基址失效。
5. 提交并推送 `update/latest.json` 到两个远端（Gitee raw 主基址读的就是主分支上这个文件）。
6. **关掉 VPN** 用大陆网络验收：关于页「检查更新」应出现更新弹窗 →「立即更新」应能下载并进入安装页。
7. 抽查回退源：`curl -sI https://github.com/greatleo31/daily-asking/releases/latest/download/latest.json`
   应为 200/302，且返回内容里的 `url` 指向同镜像 APK。

> 已踩过的坑（2026-09）：清单停留在 `10202/1.2.2`，而实际上传的 APK 是 `10203/1.2.3`，
> 装了该 APK 的用户永远判定为「无更新」；同时 GitHub 侧没有 `update/latest.json`，回退源 404。
> 第 2、4 步就是为堵这两个洞加的。

## 7. 已知限制

- **Release 构建的签名**：`android/key.properties` 存在 → 用其中的正式签名；不存在 → 退回 debug
  签名（便于本机/演示安装）。keystore 已于 2026-09-12 生成（`D:\keys\liuhen-release.jks`，别名
  `liuhen`，SHA-256 指纹 `B0:60:4C:A5:…:48:39`），**自 v1.2.4 起 release 包使用正式签名**；
  换签名会改变 APK 的 `sha256`，必须重新生成各镜像的 `latest.json`，且已装 debug 签名版本
  （≤ v1.2.3）的用户只能**卸载重装**（local-first 数据会丢，先导出）。
- 下载采用系统 DownloadManager，行为受系统通知渠道管理；安装后由用户点通知或系统安装页完成。
- 生产非 VPN 可达性依赖真实大陆可达镜像；仅配置 GitHub 源时大陆用户仍可能全部超时（回退链无镜像可退）。
- **DownloadManager 走系统代理，而 Dart 侧 http 不走**：设备配了 HTTP 代理时，检查更新会成功、
  下载却失败（代理不可达时）。原生侧在下载失败后会 toast「更新下载失败，请重试」，但**应用内
  先提示的是「已开始下载」**，真实结果要等系统回调，观感上有落差。
- **「自动更新」不等于静默安装**：开启后只是自动下载并直接拉起系统安装页，最终仍需用户手动
  点「安装」；且该提示（SnackBar）在下载很快时会被安装页盖住，用户往往只看到安装页。
- 自动更新开关默认关时，启动检查只给一次轻提示（SnackBar「发现新版本 X」+「查看」，10 秒后
  自动消失）；用户没看到又不主动进「设置 → 关于留痕」点「检查更新」，仍可能错过新版本。
- `minVersionCode` 表示**不再支持的最低版本**：当前 `versionCode` 低于它即按强制更新处理
  （`UpdateInfo.isMandatoryFor`）。不支持"先装中间版本"的渐进引导——低于门槛的版本只能一步升到
  清单里的目标版本。
- 已安装的旧版本用的是**构建时注入**的更新源列表；更换基址后，旧版本仍会按自己内嵌的地址检查
  （新基址要在下一次发版的包里才生效）。
